1. Project Overview
SpendSense AI is a production-level, full-stack web application built on the MERN stack (MongoDB, Express.js, React.js, Node.js) powered by Google Gemini AI. The application helps individuals and small teams intelligently track, analyse, categorise, and forecast their expenses — going far beyond a simple CRUD tracker by embedding AI at every meaningful touchpoint.
 
This project is intentionally scoped to demonstrate senior-level engineering decisions: clean architecture, proper JWT-based authentication, role awareness, AI integration, real-time feedback, and a polished UI — all qualities that stand out on a technical resume.

3. Feature Deep-Dive
3.1  AI Core Features (Powered by Google Gemini)
All AI calls use the Gemini 1.5 Flash model (free tier — 15 req/min, 1M tokens/day). Prompts are constructed server-side inside dedicated service files, keeping the API key safe and ensuring clean separation of concerns.
 
Feature 5 — Smart Category Auto-Tag
•	Trigger: fired on every new expense save (can be bypassed by user if they manually select a category).
•	Prompt: sends merchant name + description to Gemini and requests a single category label from a fixed enum of 12.
•	12 Categories: Food & Dining, Transport, Shopping, Entertainment, Health & Fitness, Utilities, Housing, Education, Travel, Personal Care, Investments, Other.
•	UI: category field shows a spinner while AI processes, then snaps to the result. User can override.
Feature 6 — AI Weekly Spending Insights
•	Cron job triggers every Sunday at 00:00 UTC (node-cron) per user with activity.
•	Collects past 7 days of expenses, sends aggregated JSON to Gemini, stores the markdown response in MongoDB.
•	Dashboard shows the latest insight in a collapsible card with a "View History" drawer.
•	Prompt includes prior-week data for comparative language ("You spent 23% more on Food this week").
Feature 7 — AI Budget Advisor
•	User sets a monthly budget cap per category or a global cap on the Profile/Budget page.
•	When the user visits the Budget page, a fresh Gemini prompt is fired with: current month spend vs cap, daily average spend, days remaining in month.
•	Gemini returns: risk level (on track / at risk / over budget), predicted end-of-month total, and 3 actionable saving tips.
•	Response is cached (30 min) to avoid excess API calls.
Feature 8 — Natural Language Expense Add
•	Input field accepts free text, e.g., "Coffee at Tim Hortons 350 rupees yesterday".
•	Gemini extracts: amount (number), currency hint, merchant, date (relative or absolute), category suggestion.
•	Returns structured JSON that pre-fills the expense form. User reviews and confirms with one click.
•	Saves enormous UX friction for mobile users who prefer typing over form fields.
Feature 9 — Spending Forecast
•	Uses last 60 days of expense data to compute a linear regression trendline (calculated in Node.js, no external ML library needed).
•	Sends the regression result + current month data to Gemini for a plain-English forecast message.
•	Displayed as a projected line on the monthly trend chart with a shaded confidence band.
Feature 10 — Anomaly Detection
•	On every expense save, the server checks if the new expense amount is > 2 standard deviations above the user's historical category average.
•	If flagged: Gemini generates a one-sentence explanation ("This purchase is 3x your usual Food & Dining spend").
•	User sees an amber warning banner on the expense detail page and in the notification centre.
 
3.2  Core Features (Auth & CRUD)
Feature 1 — JWT Authentication
•	Access token: 15 min expiry, stored in memory (React state / context).
•	Refresh token: 7 days expiry, stored in httpOnly cookie — XSS-safe.
•	Silent refresh: Axios interceptor auto-calls /api/auth/refresh before any failed 401.
•	Registration includes email verification link (Nodemailer + Ethereal for free SMTP in dev).
Feature 3 & 4 — Expense & Income CRUD
•	Both share a unified Transaction model with a type field (expense | income).
•	Receipt image upload via Multer → Cloudinary free tier (10GB storage).
•	Soft-delete pattern: deleted field + deletedAt timestamp so data is recoverable.
•	Pagination: cursor-based on the list view for performance (no offset pagination).
Feature 16 — Recurring Expenses
•	Recurring flag + frequency (daily | weekly | monthly | yearly) stored on the transaction.
•	node-cron job runs daily, finds due recurring templates, clones them with today's date.
•	Dashboard widget shows upcoming recurring expenses for the next 7 days.
 
3.3  Analytics Features
Feature 11 — Dashboard KPI Cards
•	4 animated counter cards: Total Spent (month), Total Income (month), Net Balance, Savings Rate %.
•	Cards use CountUp.js for smooth number animation on mount.
•	Colour coding: net positive = green, negative = red.
Feature 12 — Category Breakdown (Drill-down)
•	Built with Recharts PieChart / RadialBarChart hybrid.
•	Click on a category slice → URL changes to /dashboard?category=food → list below filters automatically.
•	Breadcrumb shows "All Categories > Food & Dining" for clear navigation state.
Feature 15 — Export Reports
•	PDF export: jsPDF + autoTable plugin renders a formatted table with logo, date range, totals.
•	CSV export: Papa Parse on the client formats data and triggers browser download.
•	Both exports respect the current active filter state.

4.2  Routing Architecture
React Router v6 is used with a nested layout approach to avoid duplicated header/sidebar code:
 
•	PublicLayout — shared by Landing, Login, Register (no sidebar; minimal header).
•	ProtectedLayout — shared by all authenticated pages. Contains: Sidebar (desktop), TopBar, NotificationBell, UserAvatar dropdown.
•	AuthGuard component wraps all protected routes; it silently attempts token refresh before redirecting.
•	Outlet-based layouts ensure the sidebar and topbar re-render only once, not per navigation.
•	Lazy loading (React.lazy + Suspense) applied to Analytics and Budget pages to reduce initial bundle size.

4.2  Transaction Service — Anomaly Detection
Called after every new transaction save. Uses pure Node.js statistics (no ML library).
 
async function checkAnomaly(transaction, userId) {
  // Fetch last 30 transactions in same category
  const history = await Transaction.find({
    user: userId, category: transaction.category,
    type: "expense", deleted: false
  }).limit(30).select("amount");

  if (history.length < 5) return; // Not enough data

  const amounts = history.map(t => t.amount);
  const mean = amounts.reduce((s, v) => s + v, 0) / amounts.length;
  const std  = Math.sqrt(amounts.reduce((s, v) => s + (v-mean)**2, 0) / amounts.length);

  if (transaction.amount > mean + 2 * std) {
    // Flag and generate AI explanation
    const explanation = await aiService.explainAnomaly(transaction, mean);
    await Transaction.findByIdAndUpdate(transaction._id, { isAnomalous: true });
    await notificationService.create(userId, "anomaly", explanation);
  }
}
 
4.3  Budget Service — Forecast
Linear regression computed server-side. Result enriched with AI commentary from Gemini.
 
async function getForecast(userId) {
  // Fetch 60 days of daily expense totals
  const dailyTotals = await Transaction.aggregate([
    { $match: { user: userId, type: "expense", deleted: false,
                date: { $gte: sixtyDaysAgo } } },
    { $group: { _id: { $dateToString: { format: "%Y-%m-%d", date: "$date" } },
                total: { $sum: "$amount" } } },
    { $sort: { _id: 1 } }
  ]);

  // Linear regression (least squares)
  const n = dailyTotals.length;
  const sumX = dailyTotals.reduce((s, _, i) => s + i, 0);
  const sumY = dailyTotals.reduce((s, d) => s + d.total, 0);
  const sumXY = dailyTotals.reduce((s, d, i) => s + i * d.total, 0);
  const sumX2 = dailyTotals.reduce((s, _, i) => s + i * i, 0);
  const slope = (n * sumXY - sumX * sumY) / (n * sumX2 - sumX ** 2);
  const intercept = (sumY - slope * sumX) / n;

  const daysLeft = getDaysLeftInMonth();
  const projected = currentMonthSpend + (slope * daysLeft + intercept * daysLeft);

  // AI commentary
  const commentary = await aiService.forecastComment(projected, budget, user.currency);
  return { projected, slope, intercept, commentary, dailyTotals };
}
 
4.4  Auth Service — Token Strategy
•	Access Token: signed with 
Access Token: jwt.sign({ userId, email }, ACCESS_SECRET, { expiresIn: "15m" }). Stored in React memory (AuthContext state). Never in localStorage.
Refresh Token: jwt.sign({ userId }, REFRESH_SECRET, { expiresIn: "7d" }). Sent as httpOnly; Secure; SameSite=Strict cookie. Hashed before storing in DB.
Token Rotation: On each /refresh call, the old refresh token is removed from the DB and a brand-new one issued. Prevents replay attacks.
Axios Interceptor: On any 401 response, the frontend interceptor silently calls /auth/refresh, retries the original request with the new access token, and redirects to /login only if refresh also fails.

5.2  auth.middleware.js
const protect = asyncHandler(async (req, res, next) => {
  const token = req.headers.authorization?.split(" ")[1]; // Bearer <token>
  if (!token) throw new ApiError(401, "Not authenticated");

  const decoded = jwt.verify(token, process.env.ACCESS_TOKEN_SECRET);
  const user = await User.findById(decoded.userId).select("-password -refreshTokens");
  if (!user) throw new ApiError(401, "User not found");

  req.user = user;
  next();
});

const errorHandler = (err, req, res, next) => {

};

  return config;

// Response interceptor: silent refresh on 401
api.interceptors.response.use(
  res => res,
  async err => {
    if (err.response?.status === 401 && !err.config._retry) {
      err.config._retry = true;
      const { data } = await api.post("/auth/refresh");
      setAccessToken(data.accessToken);
      err.config.headers.Authorization = `Bearer ${data.accessToken}`;
      return api(err.config);  // Retry original request
    }
    return Promise.reject(err);
  }
);

cron.schedule("0 0 * * 0", async () => {
  console.log("[CRON] Weekly insight generation started");
  const users = await User.find({ isEmailVerified: true,
                                  "notifPrefs.weeklyInsight": true });

      const [thisWeek, lastWeek] = await Promise.all([

      });
    } catch (err) {
      console.error(`[CRON] Insight failed for ${user._id}:`, err.message);
    }
  }
});
